# Primordium

Процедурная симуляция искусственной жизни на **Godot 4.3 C#**. Seed задаёт искусственные элементы, молекулы и геологические условия. Существа исполняют случайные геномы; белки, реакции, питание, движение и размножение получают смысл через отбор. Готовых классов «растение», «хищник», «песок» или «глина» нет.

Описание реализации и её границ: [модель симуляции](docs/SIMULATION.md). История работы: [журнал изменений](docs/CHANGELOG.md). Правила для следующих разработчиков: [AGENTS.md](AGENTS.md).

## Запуск и проверка

Открыть `project.godot` в Godot 4.3 mono. Сборка:

```sh
dotnet build --no-restore -p:UseSharedCompilation=false
```

Безголовое ядро, без Godot:

```sh
dotnet run -c Release --project tools/bench -- --self-test                       # ~1 мин; каждая часть печатает своё время (TIME …)
dotnet run -c Release --project tools/bench -- --self-test-one RubbleRegression  # одна часть по имени
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 10000 --every 1000 --audit
dotnet run -c Release --project tools/bench -- --seed 1 --size 64x64x64 --ticks 6000   # малый мир (ШxВxУ; по умолчанию 256x160x192)
```

Размер мира — настройка (`WorldSettings.Width/Height/Levels`): ширина и высота кратны 32 (32…1024 × 32…512), уровней 32…255. В игре — поля «Размер» в окне «Новый мир» (F4) и `--size` в командной строке. Тесты строят нужное сами: малые миры и сценарии (`tools/bench/Scenario.cs`: ровный пол, пещера, озеро заданной глубины, обрыв, пласты, два тела рядом) вместо целой планеты; на планете идёт только то, чему она нужна (старые форматы сохранений, длинные миры, детерминизм параллельных плиток).

Одиночный долгий прогон в буме может быть чуть быстрее с серверным сборщиком мусора: `DOTNET_gcServer=1 dotnet run -c Release --project tools/bench -- ...` (траектория та же, памяти примерно вдвое больше; по замеру 2026-10-08 выигрыш в пределах шума, в малых мирах — медленнее). В батчах он не включён: два процесса бума — без выигрыша при +47 % памяти, малые миры — на треть медленнее; если нужно, `--batch ... --server-gc [--gc-heaps H]`. В игре не включать: паузы до 100+ мс. Динамическая PGO включена в обоих проектах (`TieredPGO`).

Законы мира, сохранения и свои существа в bench:

```sh
dotnet run -c Release --project tools/bench -- --list-params                     # все законы: группа, значение, диапазон
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --set FaceWork=6 --param-at 3000:Gravity=0.0016
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --save /tmp/w.sav
dotnet run -c Release --project tools/bench -- --load /tmp/w.sav --ticks 2000   # продолжает с того же тика, тот же хеш
```

Законы задаются одинаково для одиночного прогона, серии (`--batch`) и длинного теста (`ParamHook`, через `ParamRegistry`): `--preset путь.json` — набор законов (`ParamPreset`; не названные в нём — по умолчанию), `--set Имя=значение` — закон до создания мира (`--param` — то же самое; после `--load` — поверх законов сохранения), `--param-at ТИК:Имя=значение` — смена закона во время прогона (`World.SetParam`, попадает в журнал законов). Имена — из `--list-params`, регистр не важен; значение обрезается по диапазону закона, прогон печатает, что установлено. Неизвестное имя — ошибка до старта. `--save` пишет мир в конце прогона, `--load` продолжает сохранённый (вместе с балансом энергии). `--self-test-cave` — только тест климата пещер, `--self-test-geochem` — только тест геохимии. `--self-test-sun` — только тест неба (длина дня, приток фотонов, затенение, затмения, вспышки). `--self-test-wear` — только тест фотоповреждения и износа вещества тела (сохранение атомов, потоки баланса, «запечатанное» тело без поглощения). `--self-test-climate` — только тест нестационарного климата и катастроф. `--self-test-water` — только тест течений, плавучего льда и воды в пещерах. `--climate [--seeds 1-8] [--days 40]` — расписание циклов климата по сидам без прогона: периоды наклона, прецессии, эксцентриситета и дрейфа солнца, дни, когда лето на 65° ниже порога ледниковья, дни мегаизвержений. `--catastrophe-at "ТИК:spec"` — катастрофа между тиками (как `--param-at`, попадает в журнал законов; spec: `iceage days=5`, `flood k=1`, `volcano x=-1 y=-1 blocks=60 ash=0.4`, `flare power=20 days=0.25`, `drought x=100 y=60 r=24 days=5 dt=8`, `poison x=100 y=60 r=8 n=30`). Серии (`--batch`) пишут рядом с CSV каждого прогона `*.events.csv`: события климата, игрока и темпа эволюции с тиками. `--sun [--seeds 1,2,3]` — таблица длины дня по широтам и сезонам, климат широты старым и новым законом, расписание затмений и вспышек первых 12 000 тиков и годовой приток фотонов мира без жизни против прежнего закона. `--geochem [--seeds 1-4] [--ticks 3000]` — химия мира, состав породы на 0/3/10/30/60 уровнях под верхом столба, выбросы вулканов, что держат тела и на что нацелены их белки. `--resources [--seeds 1-4] [--ticks 6000] [--from 3000]` — куда идут газ воздуха и рыхлое вещество по регионам 32×32: запасы, поглощение, выброс и смерть, диффузия, распад и дождь, за сколько суток регион опустел бы, что держат тела и сколько они вообще поглощают (`World.ResProbe`, только наблюдение). `--self-test-resources` — только тест ресурсов. `--invade [дизайн.json] [--seeds 1-6] [--at 2000] [--ticks 8000] [--count 5] [--spots 6] [--design Крот|дизайн.json]` — посадить пример по имени (на любом языке) или файл дизайна из конструктора существ (вещество и энергия извне) и следить за его линией: число тел, глубина, крыша, доля глубинного элемента. `--export-designs каталог` записывает встроенные примеры файлами JSON — заготовки для своих дизайнов. `--plant-population файл.json [--at x,y] [--local] [--local-energy] [--no-relations] [--no-remap]` — до прогона вставить шаблон популяции (по умолчанию вещество и энергия извне; другая химия сопоставляется, каждая замена печатается), в конце — сколько живо в вставленных линиях; `--copy-population вывод.json [--copy-lineage ID | --copy-area x,y,r]` — после прогона скопировать линию (по умолчанию самую большую) или круг тел в файл. `--self-test-population` — только тест шаблонов популяций. `--self-test-infra` — только тесты законов (в том числе смена законов посреди прогона под балансами), сохранения, `lifeSeed`, текста генома, своих существ и хроники. `--chronicle` печатает хронику мира по мере событий (`!` — важное); `--log` добавляет в CSV число событий, важных и окаменелостей, а также все дорожки хода эволюции (`EvolutionHistory.Names`: `adaptive`, `novelty`, `code_used`, `niches`, `mrca_age`, `pair_dist`, …, `progress_index`) и память наблюдателя `evo_mb`; на каждой отметке печатается строка `progress:`. Те же колонки попадают в `runs.csv` и `summary.csv` серий и в `--compare`. `--self-test-evolution` — только тест хода эволюции. Метрики эволюции (`EvoMetrics`, строка `evo:`, колонки `--log`, `runs.csv`, `--compare` и окна «Метрики» F12) включают также: где живут тела — `roofed_share` (доля под крышей), глубина под верхом столба `body_depth_mean`/`body_depth_p90`/`body_depth_max`, `depth_levels_eff` (e^H по уровням глубины), `mine_depth` и `mined_n` (средняя глубина и число молекул, вырванных из породы с прошлой отметки); неоднородность по регионам 32×32 — `pop_moran` и `diet_moran` (индекс Морана численности и долей питания), `pop_regions_eff`, `diet_beta_rel` (доля энтропии питания, объяснённая регионом); колебания долей питания — `osc_score`, `osc_p`, `osc_lag`, `osc_lead`, `osc_follow`, `hunt_score`, `hunt_p`, `osc_p_circ`, `hunt_p_circ` (направленный лаг между изменениями двух питаний против перемешанных суррогатов — мягкий p — и циклически сдвинутых — строгий p, по последним ≤ 48 отметкам; нужно хотя бы 17 отметок с одинаковым шагом, для циклов — `--every 100`–`250`). Определения — в `docs/SIMULATION.ru.md`, «Метрики эволюции». Участки до прогона: `--copy-region x,y,w,h файл [--copy-levels z0,z1] [--copy-no-bodies]` пишет участок (`.region` или `.region.json`), `--paste-region файл --at x,y [--rotate k] [--paste-mode above] [--no-bodies] [--dz n]` вставляет его (печатает перенесённое и проводки руки; с `--audit` бюджеты проверяются как обычно); `--self-test-region` — только тест участков.

`--audit` считает элементы в породе, телах, белках, дробном поглощении, атмосфере, осадках и захоронениях. Отдельно вычитает учтённый приток из недр и от руки. Рядом печатает энергетический баланс: запас по резервуарам, потоки (свет, удары, вулканы, рука, свои существа, `EnergyK`, тепло затрат, распада, смерти, давления) и дрейф `запас − (входы − выходы)` с допуском (см. «Балансы» в docs/SIMULATION.md). На каждой отметке печатается строка `evo:` — метрики эволюции (разнообразие геномов и линий, смена линий, белки, питание, новизна); `--log` пишет их колонками. `--pop N`, `--noabio`, `--probe` и `--genome ...` помогают воспроизводить эксперименты. Профиль выводит время неба, диффузии, химии/климата, опор (по частям) и агентов (работа квадратов и самый медленный квадрат); `--ops` добавляет время по командам VM. Мир детерминирован: тот же seed даёт ту же траекторию, поэтому оптимизации удобно сравнивать до/после.

Решения о законах принимать по сериям, а не по одному прогону: один сид в разных версиях давал от 36 тыс. до 116 существ.

```sh
# 16 сидов × 3 повтора по 6000 тиков, отметки каждые 1000, 3 процесса одновременно
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --every 1000 --jobs 3 --out runs/base
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --every 1000 --jobs 3 --out runs/base --resume   # после сбоя: только недоделанные
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --every 1000 --out runs/try --set CostBase=0.02
dotnet run -c Release --project tools/bench -- --compare runs/base/runs.csv runs/try/runs.csv
dotnet run -c Release --project tools/bench -- --long-test            # сиды 1,2,3 по 20 000 тиков: атомы, энергия, детерминизм, обвалы
# два этапа: отсев на малых мирах, подтверждение на полных
dotnet run -c Release --project tools/bench -- --batch --seeds 1-32 --reps 2 --ticks 6000 --size 64x64x64 --out runs/screen --set CostBase=0.02
dotnet run -c Release --project tools/bench -- --batch --seeds 1-32 --reps 2 --ticks 6000 --size 64x64x64 --out runs/screen-base
dotnet run -c Release --project tools/bench -- --compare runs/screen-base/runs.csv runs/screen/runs.csv
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --out runs/try --set CostBase=0.02   # что прошло отсев — на полных мирах
# одна серия на двух машинах и сборка результата
dotnet run -c Release --project tools/bench -- --batch --seeds 1-32 --ticks 6000 --out runs/a --shard 1/2 --machine mac    # на первой
dotnet run -c Release --project tools/bench -- --batch --seeds 1-32 --ticks 6000 --out runs/b --shard 2/2 --machine cloud  # на второй
dotnet run -c Release --project tools/bench -- --merge runs/all runs/a runs/b
# прерывистое равновесие: ледниковье игрока на тике 3000 против того же мира без него
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --ticks 10000 --every 250 --out runs/ctrl
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --ticks 10000 --every 250 --out runs/ice --catastrophe-at "3000:iceage days=4"
dotnet run -c Release --project tools/bench -- --punctuated runs/ice --control runs/ctrl
```

- **Две ступени.** `--size ШxВxУ` — для `--batch` и одиночного прогона. Сначала дёшево отсеивать много вариантов на малых мирах (`--size 64x64x64`: ~1/30 вокселей, прогон в 6000 тиков за секунды), потом немногие прошедшие подтверждать на полных мирах (без `--size`) и только по ним решать. Малый мир получает первые тела, вулканы, удары и сползание пропорционально площади (`World.PerArea`), поэтому сравнимы величины на клетку (плотность, диеты, россыпь), а не суммы (численность, число линий, вымирание при пороге 10 тел). Если важна широта — оставить высоту 160 (`--size 64x160x96`). Размер входит в подпись серии (`--resume`).
- `--batch`: `--seeds 1-16` (или `1,4,7-9`), `--reps R` (повтор 0 — мир сида, r > 0 — тот же мир с другой «жизнью»: `WorldSettings.LifeSeed = r` меняет только первые тела и случайные потоки существ), `--ticks`, `--every`, `--pop`, `--noabio`, `--tile`, `--audit` (энергия и атомы в каждой строке), `--jobs J` (процессов одновременно; по умолчанию — число производительных ядер: на macOS `sysctl hw.perflevel0.physicalcpu`, на M4 это 4; на Intel Mac — физические ядра; в других системах — логические процессоры), `--out каталог`, пороги `--extinct N` (≤ N тел в конце; 10) и `--boom N` (> N на любой отметке; 20000), законы `--preset`/`--set`/`--param-at` (каждый прогон получает их как есть; колонка `params` в `runs.csv`). `--server-gc` — каждый прогон с серверным сборщиком мусора (`DOTNET_gcServer=1`; `--gc-heaps H` ограничивает число куч), по замеру не выгоден. Каждый прогон — отдельный процесс; в строке «done» и в конце серии — процессорное время и пик памяти (строка `resources:` журнала прогона). Результат: `runs.csv`, `summary.csv`, журналы прогонов в `runs/` и таблица: численность на отметках, вымирания, бумы, температура, метрики эволюции, мс/тик.
  - **Потоки.** `--threads T` (по умолчанию 1) — каждый прогон получает `DOTNET_PROCESSOR_COUNT=T`, и его мир шагает на T потоках (`World.Step` берёт число рабочих из `Environment.ProcessorCount`); `--threads 0` — сколько ядер у машины. Траектория от числа потоков не зависит. В серии выгоднее один однопоточный мир на ядро: многопоточные миры в нескольких процессах только мешают друг другу (на общей машине загрузка доходила до 140 на 10 ядрах). Одиночный прогон вне серии на общей машине тоже лучше запускать с `DOTNET_PROCESSOR_COUNT=1`.
  - **Очередь с продолжением.** Законченный прогон (процесс вышел без ошибки, его CSV дошёл до `--ticks`) оставляет `runs/sS_rR.done` с подписью серии: тики, шаг, законы, `--pop`, `--tile`, `--noabio`, `--audit`, версия кода, `--server-gc`. `--resume` пропускает прогоны, у которых `.done` совпадает с подписью, и делает остальные: после сбоя машины, Ctrl-C или упавшего прогона достаточно запустить ту же команду с `--resume`. Без `--resume` все прогоны делаются заново. Если подпись другая (другие законы или коммит), прогон тоже делается заново: старый результат с новым не смешивается. В конце серии `runs.csv` и `summary.csv` собираются из всех CSV прогонов каталога, и сделанных раньше.
  - **Несколько машин.** `--shard K/N` берёт K-й из каждых N прогонов (по порядку сид × повтор, K с 1): одна и та же команда с `--shard 1/3`, `2/3`, `3/3` на трёх машинах делит серию без пересечений. `--machine имя` — метка машины в CSV (по умолчанию имя хоста). В каждой строке `runs.csv` есть колонки `machine` и `code_version` (коммит git из рабочего каталога, 12 знаков; `-dirty`, если есть незакоммиченные изменения отслеживаемых файлов; `unknown` вне репозитория). Каталог серии содержит `batch.txt`: подпись, сиды, повторы, доля, машина, версия, время начала.
- `--merge каталог a b …` — объединить серии (каталоги или их `runs.csv`) с нескольких машин или долей: колонки сопоставляются по имени (недостающие — пустые), строка (сид, повтор, законы, тик) берётся один раз. Повтор той же строки с другой машины сверяется по хешу состояния: одинаковый код и законы обязаны давать тот же мир везде; расхождения печатаются (`DIFFERENT HASH`, оставлена строка первого файла). Пишет `runs.csv`, `summary.csv` и таблицу, как серия; результат годится для `--compare`.
- `--punctuated каталог [каталог …] [--control каталог …] [--window-days 4] [--burn 2000] [--perms 2000] [--onsets iceage,winter,eruption,player] [--columns new_lineages,lineages_lost]` — прерывистое равновесие (ROADMAP 9.4): растёт ли темп эволюции в первые сутки после катастрофы. Читает `runs/*.events.csv` и `runs/*.csv` серий. Начала: «началось ледниковье», «вулканическая зима», мегаизвержение, катастрофа игрока (`flare` — вспышки — если назвать в `--onsets`). Окно — `window-days` суток после каждого начала, перекрытия сливаются; тики до `--burn` не считаются нигде (основание мира — свой всплеск). Ряды темпа: видообразования, вымирания, новые доминанты хроники, их сумма `tempo_all` и колонки `runs.csv` из `--columns` (значение отметки относится к её тику). Внутри прогонов: событий в сутки в окнах и вне их, отношение в сумме по прогонам, критерий Уилкоксона для разностей по прогонам (двусторонний, точный до 30 прогонов), знаковый тест и перестановочный тест: все начала прогона сдвигаются на одно случайное смещение (сохраняются их промежутки и собственная кучность событий прогона), p — доля сдвигов с отношением не меньше наблюдаемого (односторонний). С `--control`: окна опытного прогона накладываются на контрольный прогон того же сида и повтора (тот же мир без катастрофы — серия без `--catastrophe-at`), парные разности, Уилкоксон, знаковый тест и точный тест перестановки знаков (до 20 пар; больше — 20 000 случайных). Контроль сильнее: сравнение идёт в те же тики того же мира, без примеси тренда времени.
- `--compare a.csv b.csv`: медианы и квартили, разность медиан с бутстреп-интервалом, Манн — Уитни, знаковый тест по сидам, Фишер для вымираний и бумов; флаг `* differs` / `~ noise`.
- `--life N` — одиночный прогон с другим `lifeSeed`.
- `--long-test [--seeds 1,2,3] [--ticks 20000] [--every 2000]` — длинная регрессия: баланс атомов и энергии на каждой отметке, у первого сида параллельный двойник с тем же хешем состояния, и проверка, что обвалы, дробление и захоронения, осадки и реакции давления действительно происходили. `--self-test` остаётся быстрым.
- `--tournament` — турнир с предками (только наблюдение): `[--seed S | --load поздний.sav] [--ticks T] [--snap-every E] [--ancestors ранний.sav[,ещё.sav]] [--top 3] [--count 20] [--spots 4] [--arena-ticks 3000] [--reps 3] [--energy 40] [--residents]`. Предки — `top` самых частых геномов (точный геном) на снимках прогона каждые E тиков или в ранних сохранениях того же сида; современники — самые частые в конце. Арена — копия конечного мира из памяти (тот же рельеф, климат, химия, законы и момент); её жители убиты (останки остаются), если не `--residents`. Каждая сторона — `count` тел (поровну по геномам и местам; места — где живут современники и где жили предки, обе стороны в каждом, порядок чередуется), тело — копия тела с этим геномом, энергия `--energy` у всех, вещество и энергия извне. Через `arena-ticks` считаются живые потомки сторон; повторы — другие места. Итог по каждому снимку: живых по расстановкам, доля современников, побед и вывод («побеждают современники» > 60 %, «предки» < 40 %, иначе «поровну»). Основной мир не трогается.
- `--food-chain [--seeds 1-2 | --load путь.sav] [--ticks 6000] [--every 2000] [--by lineage|genome] [--edge 0.05] [--min-share 0.005] [--top 6]` — кто кого ест (только наблюдение, `World.FoodProbe`): по линиям (или точным геномам) молекулы, полученные из среды (поглощение, добыча) и от тел (`attack`, `take`), и убийства. За каждое окно: доля добычи, трофический уровень (1 — только среда; 1 + Σ доля·уровень источников; поедание своей линии — отдельно, столбец «своя линия»), средний (по полученным молекулам) и наибольший (линии ≥ `min-share` всех молекул), длина цепочки (узлов на самом длинном пути по рёбрам ≥ `edge` молекул едока) и самые крупные рёбра. Уровень ограничен 10: такое значение — петля взаимного поедания без среды в окне. Хеш состояния печатается — проба траекторию не меняет.
- `--perf-baseline [--fixture путь.sav] [--ticks 2000] [--warmup 200] [--repeat 1] [--csv perf.csv] [--label текст]` — эталонный замер скорости (ROADMAP 10.7): загружает сейв бума, прогревает `warmup` тиков (JIT, PGO) и меряет `ticks`: стена и процессор мс/тик, все этапы `World.Prof` и `World.Detail`, работа квадратов и самый медленный, выделение памяти, сборки, пик памяти, популяция, хеш в конце (тот же хеш до и после оптимизации — та же траектория), машина и загрузка (load average). Ключ на строку, медиана повторов; `--csv` дописывает строку на повтор. Эталон не хранится в репозитории (31 МБ), а делается один раз: `--perf-baseline --make [--seed 2] [--target 15000] [--step 1000] [--max-ticks 30000]` гонит мир сида, пока в нём не станет `target` тел, и пишет `tools/bench/fixtures/boom.sav` (по умолчанию: сид 2, тик 14 000, 20 904 тела, хеш `7a9b36b320063a1f`; другой хеш — другая версия мира, и числа несравнимы со старыми записями). Сравнивать сборки на одном эталоне, Release, на свободной машине; хеш в конце 2000 тиков после 200 прогрева — `402d639e3cdf486b`. **Рецепт записи в журнал** (ROADMAP 10.7): `dotnet run -c Release --project tools/bench -- --perf-baseline --repeat 3 --csv runs/perf.csv --label "что меряем"` — печатается медиана трёх повторов (и строка каждого повтора: стена, процессор, существа, хеш), CSV получает строку на повтор; в `CHANGELOG.md` записать устройство, загрузку (`load avg` из вывода), сид и тик эталона, тики, популяцию, хеш, медиану и разброс повторов и число потоков (`DOTNET_PROCESSOR_COUNT`, если задан). Разброс больше ~10 % — машина занята, замер повторить. На общей машине `DOTNET_PROCESSOR_COUNT=1` даёт однопоточный замер (процессорная работа в нём втрое меньше, чем на всех ядрах; сравнивать только однопоточный с однопоточным).

Godot принимает `--abio` и `--strikes` (самозарождение и удары с орбиты в новом мире **по умолчанию выключены**: жизнь запускает игрок — N, свои существа — или клавиши A и ⇧X), `--seed N`, `--warm N`, `--slice ROW`, `--zoom Z`, `--shot /path/image.png`, а для снимков кисти `--tool 1..5 --paint K` (K мазков в центре экрана перед снимком). Окна для снимков: `--open laws,newworld,saves,creator` (через запятую; `newworld:more` — с раскрытым «Дополнительно», `creator:looks` и `creator:help` — вкладки конструктора; `chronicle`, `chronicle:fossils` — хроника и список окаменелостей; `evolution` — ход эволюции; `tree`, `tree:lineages` — древо жизни (кладограмма, линии во времени); `metrics`, `metrics:genomes+used_code` — окно метрик (с выбранными рядами); `catastrophes` — катастрофы; `matter`, `matter:N` — библиотека веществ с N-м веществом списка, `matter:pN` — взять N-е в кисть 1 и закрыть окно (с `--paint K` — насыпать его в центре); `fossil`, `fossil:bio`, `fossil:ancestry` — самая важная окаменелость). `--seltracked` выбирает живое существо с самой длинной биографией, `--tab bio` открывает в карточке вкладку «Биография». `--load путь.sav` загружает сохранение вместо нового мира, `--selcave` выбирает тело под самой толстой крышей и делает разрез через него. `--lookeclipse` подводит камеру к тени спутника, если идёт затмение, `--looksun` — к дневной стороне (снимки неба). `--sidebar expanded|collapsed` — боковая панель развёрнута или свёрнута (только на этот запуск). `--open none` — без окон (и без восстановления открытых из `ui.json`). `--plant K` — посадить K тел первого примера у крупнейшей линии и выбрать одно (снимки метки подсаженных). `--overlay N` — оверлей поверхности по номеру (8 — вещество: порядок и упаковка, 15 — ареалы ветвей). `--uitest` — сценарий проверки окон: смена закона, быстрое сохранение, посадка всех примеров (извне и из местного вещества), быстрая загрузка; итоги и всплывающие сообщения печатаются строками `uitest:` и `notice:`. После прогрева снимок делается через несколько кадров. Пока продолжаете менять код, запускайте долгие прогоны из отдельной копии сборки, чтобы не перезаписывать исполняемый DLL.

Мир шагает в отдельном потоке (`src/SimRunner.cs`), кадр его не ждёт: вид рисует последний опубликованный снимок существ, а действия руки, N, X, A, пауза, шаг, скорость и промотка уходят командами и применяются между тиками. Скорость `×N` — цель N тиков за 1/60 с (как прежние «тики за кадр» при 60 кадрах/с), если мир успевает.

Замер производительности: `--perf N` печатает каждые N кадров строку `PERF` (кадр, тики/с и мс на тик, этапы `World.Prof`, шаги вида, HUD, загрузки на GPU, примитивы и вызовы отрисовки), `--perfquit K` выходит после K строк, `--pauseafter K` ставит паузу после K строк, `--perfshow` сразу открывает оверлей F3. Ещё `--tpf N` (начальная скорость), `--overlay K` (карта поверхности), `--viewthreads N` (потоки заполнения вида, 0 — только главный). Пример:

```sh
Godot --path . -- --seed 2 --warm 10000 --perf 120 --pauseafter 3 --perfquit 6
```

## Законы мира, сохранения, свои существа

Всё это доступно в окнах игры (боковая панель слева и клавиши F1–F12). Окна перетаскиваются за заголовок, меняют размер за правый нижний угол и запоминают положение и открытость в `user://ui.json` (на macOS — `~/Library/Application Support/Godot/app_userdata/Primordium`). Пока курсор над окном, карта не двигается и кисть не рисует; пока печатаете в поле, клавиши не управляют игрой. Итоги команд (сохранено, посажено, закон изменён, ошибки) всплывают сообщениями слева внизу.

- **Законы мира (F2).** Группы реестра слева, поиск по имени и описанию. У каждого закона ползунок, поле числа, диапазон, описание (подробности — во всплывающей подсказке), отметка «изменён» и сброс. Ползунок применяется при отпускании (сила тяжести и прочность пересчитывают опору всей карты), число — по Enter. Законы, которые читаются только при создании мира, заблокированы с пометкой «только для нового мира». Внизу — «всё по умолчанию» и наборы законов: сохранить текущие (в `user://presets/`, только отличия от умолчаний), применить, удалить.
- **Новый мир (F4).** Seed (и случайный), начальное население (0 — пустой мир), самозарождение, удары с орбиты, солнечные вспышки и затмения (законы `Flares`, `Eclipses`), законы: текущие, по умолчанию или набор. «Дополнительно» раскрывает все законы нового мира, включая читаемые только при создании. Мир строится в потоке симуляции, игра при этом не замирает. R и ⇧R работают как раньше.
- **Сохранения (F6).** Слоты в `user://saves/`: миниатюра карты в момент сохранения (`имя.png` рядом с `имя.sav`), сутки, тик, население, seed, дата, заметка. Сохранить в новый слот, перезаписать, удалить (второй клик подтверждает), загрузить. Автосохранение каждые N минут (0 — выключено, по умолчанию 10) по кругу в K файлов `autosave_N.sav`. F5 и F9 — быстрые сохранение и загрузка.
- **Библиотека жизни (U).** Вкладка «Существа» — дизайны из `user://creatures` (те же, что в конструкторе) с проверкой для этого мира; «Посадить кистью (5)» — с настройками конструктора. Вкладка «Популяции» — шаблоны в `user://populations/`: «Линию выбранного», «Ветвь из древа (F1)», «Область кистью (5)» копируют живые тела (геном байт в байт, молекулы, белки, энергию, облик, места относительно друг друга, родство) в файл JSON; путь файла виден в окне, файл можно перенести на другую машину («Импорт»/«Экспорт», «Обновить»). «Вставить кистью (5)»: из местного вещества и энергии (не хватает — тело не делается, ничего не берётся) или принесённых извне (учёт в балансе руки); «Сохранить линии и родство», «Перенацелить гены белков». Шаблон из мира с другой химией сопоставляется с ближайшими видами этого мира — окно перечисляет, какие молекулы на что заменятся, и предупреждает о номерах видов в геномах. Вставленные отмечены как посаженные игроком, вставка — событие хроники.
- **Конструктор (F7).** Библиотека дизайнов `user://creatures/` (при первом запуске туда кладутся примеры, «Вернуть примеры» восстанавливает удалённые): новый, копия, сохранить, удалить, «взять у выбранного» — геном, тело и облик выбранного на карте существа. Геном пишется текстом с подсветкой команд; строки с ошибками подсвечиваются, под редактором — ошибки или длина, число команд и генов белка. Вкладка «Тело и посадка»: молекулы тела (номер вида этого мира, `gas`, `any`) и их число, энергия, откуда вещество и энергия (местные или принесённые извне — с объяснением учёта), сколько сажать, и сколько нужного рыхлого вещества и энергии местных распадов есть у курсора. «Облик» — свой цвет и форма или облик из генома, портрет по геному. «Справка» — все команды ВМ из её таблицы с кратким описанием. Кисть 5 сажает дизайн по клику. Посаженные отмечены в карточке существа: «от игрока: посажен из дизайна …» или «потомок дизайна …».
- **Хроника (F8).** Лента событий мира: первые белки и реакции, открытия пород, смены питания линий, рекорды глубины и прочие рекорды, первый пловец, житель пещер, хищник, паразит, видообразование, вымирание, новый доминант, удары с орбиты, солнечные вспышки (облучено, мутаций, погибло), затмения (полоса тени) и вулканы, действия игрока (посадка, законы, сохранения). Фильтры: типы (с числом событий каждого), линия, время, «только важное». Клик по событию: живое существо — камера летит к нему и выбирает его, мёртвое — открывается его окаменелость, иначе камера летит к месту. Вкладка «Окаменелости» — все сохранённые тела. Важные события — цветные чёрточки над графиком населения (наведение — подпись).
- **Катастрофы (F11).** Ледниковье на N суток, потоп (+K блоков моря), вулканическая зима (мегаизвержение у вулкана или в выбранном месте), сильная солнечная вспышка, засуха и отравление в выбранном месте (центр экрана или числа x, y, радиус). Отравление рассыпает самую реакционную по закону реактивного урона молекулу мира или любое вещество из библиотеки (J); вредит ли оно, видно по строке под кнопкой. Это те же законы, что и в мире (`World.ClimateCycles`): вещество, вода и энергия учитываются, кнопка нажимается дважды, катастрофа записывается в хронику и в журнал законов. Внизу — эпоха и счётчики.
- **Участки (Y).** «Выделить на карте» и протянуть прямоугольник (размер виден в окне и над контуром), уровни — вся высота или от/до, «с существами», «Копировать в библиотеку» `user://regions/` (файл `.region` и картинка сверху). «Вставить» берёт участок кистью: контур с учётом поворота (0/90/180/270°) идёт за курсором, щелчок вставляет; режимы «заменить рельеф» и «только над землёй», «существа» (выкл. — только вещество), сдвиг по уровням. Вынутое и внесённое учитывается как работа руки (атомы, энергия, вода), обвалы после вставки — физика. Участок из мира другой химии: виды сопоставляются ближайшим здешним (окно предупреждает и показывает сопоставление), новых молекул нет. Экспорт JSON / двоичный, импорт, удаление.
- **Библиотека веществ (J).** Вещество — рецепт из настоящих молекул этого мира: доли видов, порядок решётки (он задаёт упаковку и пористость) и форма (блоками или рыхло/распылить); имя, вид («яд», «минерал»…) и цвет — только метки. Список: посчитанные для seed (самый твёрдый кристалл, самое плотное, самая реакционная смесь, самое летучее, энергоёмкая залежь, мягкая насыпь, инертная засыпка — всё по формулам из химии мира), образцы и черновики сессии, файлы `user://materials/`. «Взять из мира»: верхний блок под курсором (точно: молекулы и порядок), рыхлое там, тело выбранного. Справа — что это по формулам движка: молекул на блок и на объём, порядок и пористость, плотность, связность, барьер грызения, сколько держит блок, реактивный урон, энергия связи; картинка блока (грани и блеск по порядку, темнее — плотнее). «Насыпать кистью 1» — кисть сыплет ровно этот рецепт (вещество и его энергия связи записываются как принесённые рукой; у порядка в движке нет энергии — высокий порядок остаётся содержимым игрока). Файл из мира с другой химией переводится на ближайшие по свойствам молекулы этого мира — с показом соответствия и предупреждением; новых молекул не появляется. Оверлей 8 (M) — «вещество»: упорядоченные блоки светлее, с гранями и блеском, плотные темнее; в разрезе (C) — каждый уровень.
- **Ход эволюции (F10).** Пять дорожек на общей шкале времени: новизна (компоненты, чья активность выше нейтральной тени: мир, контрольная тень и их разность), сложность (используемый код, белков и реакций на тело, масса), экология (ниши, разнообразие питания, крупные линии, доли под землёй и в воде), темп (смены доминанта, видообразования и вымирания на 10 тыс. тиков, дрейф самого частого генома), филогения (возраст MRCA крупнейшей линии, среднее попарное расстояние, живые генотипы, длина линии). Поверх — важные события хроники; наведение показывает значения и события в точке; окно времени; CSV в `user://evolution/`. Сверху — сводная **подсказка** «идёт / стагнирует / откат» (медиана трендов четырёх дорожек за `ProgressWindow`): подсказка, а не вывод — смотреть надо на дорожки.
- **Древо жизни (F1).** Вкладка «Кладограмма живых»: родословная генотипов (`World.Phylo`), свёрнутая до ветвей, где не меньше выбранной доли населения (0,5–5 %, не меньше 3 тел; если ветвей больше 90, порог поднимается). Время идёт вправо; ветвь начинается с генотипа, где отделилась, и длится до сейчас, толщина — число тел, вертикальная связь — момент отделения от родителя. Наведение — линия, тела, генотипы, шагов-мутаций от корня; клик выбирает ветвь, камера летит к её старейшему живому, а на оверлее «ареалы ветвей» (галочка «ареалы на карте» или M) она с подветвями ярко, остальные серым. Вкладка «Линии во времени»: полоса каждой линии (основателя) толщиной по её численности (логарифмически) по замерам этого сеанса, треугольники — видообразования и новые доминанты из хроники, крестик — вымирание; клик — к живому представителю, у вымершей — её окаменелость. Дерево строится в потоке мира раз в секунду, только пока открыто окно или включён оверлей.
- **Метрики (F12).** Слева — метрики эволюции (`EvoMetrics`, колонки `evo:` бенча: разнообразие, поколения и код, белки, питание, новизна) и колонки хода эволюции из сейва; до 8 рядов, каждый своей полосой на общей шкале времени, со значением под курсором и важными событиями хроники. Метрики снимаются в потоке мира раз в 500 тиков (больше 2048 замеров — каждый второй выбрасывается, шаг удваивается) и живут только в этом сеансе. CSV — вся таблица в `user://metrics/`.
- **Окаменелость.** Когда жило, отчего умерло, почему сохранено, состав тела, белки, геном текстом, биография, цепочка отслеживаемых предков до основателя (клик — к живому или к окаменелости). «Воскресить» открывает её в конструкторе как дизайн — дальше кисть 5.
- **Биография** — вкладка в карточке выбранного существа: почему ведётся, родитель, предки и живые дети (ссылки), график энергии и массы, лента жизни (рождение, первые белки и реакции, уход под землю и выход, убийства, кражи, дары, облучение, рекорды, потомки, события, смерть). Выбранное существо отслеживается с момента выбора; основатели линий и посаженные — с рождения, участники событий — с события.

Ядро (команды — в `SimRunner`):
- **Законы мира** — 213 настраиваемых величин `P` (цены, скорости, пороги, прочность, климат, климатические циклы, климат пещер, геохимия, ресурсы, вода, небо: инсоляция, прозрачность, затенение, затмения, вспышки). `ParamRegistry` знает о каждой группу, описание, диапазон, шаг и меняется ли она на ходу. Меняются между тиками (`SimRunner.SetParam`), записываются в `World.ParamLog`: траектория = seed + история законов. Наборы законов — JSON (`ParamPreset`).
- **Новый мир** — `WorldSettings`: seed, начальное население, самозарождение, удары, набор законов.
- **Сохранение** — весь мир в один файл (Brotli): после загрузки он идёт ровно так же, как шёл бы исходный. Есть автосохранение по кругу.
- **Свои существа** — геном пишется текстом (по команде в строке, `GenomeAsm`), любое живое существо можно разобрать в текст. `CreatureDesign` — геном, состав тела и энергия, хранится в JSON. Сажать можно из местного вещества и энергии местных реакций или принеся их извне — тогда они учитываются в `HandInput`/`HandEnergy`. Даром ничего не появляется. Примеры: «Листок», «Крот», «Пловец».
- **Хроника** — `World.Chronicle`: события, окаменелости, родословная отслеживаемых, биографии (`Agent.Bio`). Только наблюдение: хеш мира тот же, что без неё. В сохранении. Подробно — «Хроника» в docs/SIMULATION.md.
- **Ход эволюции** — `World.Shadow` (нейтральные тени Бедау и активность компонентов), `World.Phylo` (родословная всех живых по генотипам, с обрезкой), `World.Progress` (дорожки раз в `ProgressEvery` тиков). Только наблюдение: хеш мира тот же. В сохранении (версия 4). Подробно — «Ход эволюции» в docs/SIMULATION.md.

Подробности — в [docs/SIMULATION.md](docs/SIMULATION.md).

## Материя и геология

В каждом мире четыре искусственных элемента со своими массами, сродством и валентностью. Из них генерируются 16 формул, каждая в основном и возбуждённом состоянии: всего 32 вида молекул. Звёздочка в имени означает возбуждение, а не новый элемент. Молекула имеет вектор состава, массу, энергию, связность и склонность к упаковке.

Соединение допустимо только при наличии продукта с суммой исходных составов. Распад возвращает составляющие; возбуждённый одиночный элемент может расслабиться в своё основное состояние. Свет поднимает энергию того же состава. Недопустимая реакция ничего не создаёт.

Планета — цилиндр 256×160 клеток, до 192 блоков по высоте (по умолчанию; размер — настройка мира): кора `World.Crust` = 60 блоков под самыми низкими местами, рельеф от долин до гор ~28 блоков (закон `ReliefScale` растягивает его: при 4 — ~115 блоков, самые высокие столбы ~175; по умолчанию 1, пока склоны не порождаются в пределах прочности породы), над ним ~100 блоков воздуха. На уступы выше блока тела забираются импульсом. Начальные пласты выбираются по свойствам молекул, глубине и пространственно связанным случайным полям. У каждого блока есть оставшийся состав и порядок решётки. Постройки и осадки хранят именно внесённые молекулы, включая смеси. Два нижних уровня — непроходимая граница модели недр.

## Опора, подкоп и обвал

`mine` добывает под ногами; `gnaw` — стену на высоте тела или доступный соседний пол. Когда блок исчерпан, остаётся пустота. Верхняя порода может удержаться через соседние блоки. Существа могут зайти в полость, копать дальше, родить там потомство и добывать лежащие на её полу останки. Под непрозрачным потолком нет поверхностных фотонов.

Нагрузка зависит от массы породы, захороненного вещества и массы стоящих на ней существ. В массу тела входят также дробное поглощение и материальный субстрат белков. Подъём тяжёлого тела дороже; падение тяжелее.

Монолит лучше передаёт нагрузку. Разные составы слабо сцепляются на границе; смесь ослаблена и внутри блока. Частичная добыча уменьшает несущую площадь. Опора прослеживается до заземлённой породы: висящий замкнутый пласт не может поддерживать сам себя. Прочность на сжатие растёт с боковым обжатием (Мор — Кулон): блок внутри пласта своей породы держит толщу над собой, край обрыва, отдельный столб или свободная насыпь — только собственную прочность; стык непохожих пород передаёт обжатие плохо. Перегруженная опора дробится в щебень на месте (тот же объём, меньше прочность), неподдерживаемые блоки падают, разрушая следующие опоры каскадом. Щебень, который не держит нагрузку, течёт как сыпучая масса туда, где есть место; вещество никогда не занимает меньше места, чем его объём. Раздробленная масса занимает больше места, чем решётка (разрыхление, из упаковки молекул), и выдавливает лишнее вверх или в стороны; давление уплотняет её обратно, и каждый следующий шаг уплотнения требует экспоненциально большего давления.

Существо в пути падающего блока погибает от обвала. Его молекулы, частично поглощённое вещество и белки остаются **на глубине столкновения**. Давление и температура меняют порядок этого захороненного агрегата; допустимые реакции соединяют его молекулы без изменения элементов. Перестройка влияет на механическую связность. Готового правила «труп → уголь» нет.

Карта нагрузки показывает отношение давления к прочности на сжатие; красные участки близки к перегрузке. Это не полная карта боковых напряжений. Карта решётки показывает порядок верхнего блока. В инспекторе существа есть высота, давление и прочность опоры.

## Круговорот

- Поглощение переносит вещество среды в тело, выброс возвращает его на доступную высоту.
- Белок сохраняет молекулу-субстрат. При износе и повреждении она возвращается в тело или выпадает наружу.
- Смерть возвращает состав тела; оставшаяся пригодная энергия рассеивается теплом.
- Вещество тела изнашивается (законы `PhotoDamage` и `WearK`, группа «Износ», по умолчанию выключены): пойманный фотон может разрушить возбуждённую молекулу вместо запаса энергии, а каждая молекула тела — потерять связь с телом от тепла. Молекула уходит на пол клетки своим экзотермическим распадом (энергия — теплом, поток `body decay`) или целой; чем прочнее её связность (и плотнее матрица тела для фотоповреждения), тем реже. Без этих законов свет на своих же молекулах — вечная батарея (`D1 → D1* → D1`), и тело может не поглощать вещества всю жизнь.
- Осадки собираются из фактического запаса молекул, без пересчёта энергии в «гумус».
- Выветривание и разрушение освобождают вещество блока, сохраняя его состав.
- Газ распространяется над поверхностью (скорость — закон `GasDiffK`, по умолчанию 1); дождь может адсорбировать часть существующих атмосферных молекул на породе. Они снова доступны для поглощения на открытом полу. Под крышей газ воздуха по умолчанию недоступен; закон `CaveGasK` даёт телу под крышей долю `e^(−крыша/CaveGasK)` газа своего столба (из того же запаса, что пьёт поверхность).
- Вулкан добавляет вещество из внешнего для расчётной коры резервуара; этот приток записывается отдельно.
- Абиогенез, включая N и диагностический `probe`, использует местные молекулы и энергию разрешённых реакций. Если ресурсов нет, создание не удаётся.

Материя и энергия учитываются раздельно: тепло не превращается в новые элементы. Питание использует разницу энергий состояний; свет пополняет химическую энергию. Затраты действий и жизни рассеиваются теплом. Температура и вода остаются упрощёнными климатическими полями, а не атомистической термодинамикой.

## Жизнь и геном

Геном — стековая машина: обычно 8 тактов за тик, стек и память по 16 ячеек, вызовы и переходы. Младшие 6 бит байта выбирают команду; старшие 2 — вариант или небольшое число. Мутации меняют, вставляют, удаляют и дублируют код. Полезные участки получают частичную защиту при наследовании.

`enzyme` читает три следующих байта: тип катализа, целевые молекулы, температурный оптимум и эффективность. Возможны соединение, распад/релаксация, захват света и мотор. Ген не выдаёт готовую цепочку питания: код должен обеспечить её входы и использовать выходы. Белки изнашиваются, тело требует энергии, жара и мороз повреждают его. Рост по массе позволяет телу занимать несколько клеток; родственные формы наследуют внешний вид с дрейфом.

| Группа | Команды |
|---|---|
| Стек, числа | `push lit dup drop swap over rot add sub mul div mod neg inc dec lt eq rand` |
| Управление, память | `label jmp jz jnz call ret skipz yield load store` |
| Состояние тела | `energy age have mass temp btemp gene glen` |
| Мир | `sense sensed smell light photons uv look ground` |
| Внимание и общение | `pick count feel kin ngene listen emit hurt` |
| Белки и химия | `enzyme bind split photo digest` |
| Мембрана и движение | `intake drink expel push swim` |
| Жизнь и взаимодействия | `divide mate attack take give share link inject cut` |
| Порода | `mine gnaw dig pile grow` |

`push` толкает тело мотором в одну из 4 сторон; `swim` (второе значение `nop`) — гребок вверх или вниз, только в воде. В воде тело без газа тонет и ходит по дну (вода легче любой молекулы); газ в теле — пузырь, поэтому `intake`/`expel` газа выбирают глубину. У поверхности свет и воздух, у дна останки; каждый гребок тем дороже, чем глубже (подробно — «Вода» в docs/SIMULATION.md). `dig` переносит блок целиком; `pile` собирает блок из одинаковых твёрдых молекул; `grow` выделяет агрегат из четырёх имеющихся молекул тела. Древесина не является особым материалом. Связи колонии требуют взаимного согласия. Способности и устойчивые цепочки возникают через случайный код и отбор.

## Текущий масштаб модели

Это конечная искусственная химия и приближённая механика вокселей. Решётка представлена составом, связностью и параметром порядка; явных координат атомов и расчёта упругих деформаций нет. Опорный граф выбирает один сильнейший путь на блок и может консервативно разрушать свод, который выдержал бы более точный расчёт. Вода и атмосфера пока поверхностные (в воде есть плавучесть, глубина и свет по глубине, но нет течений). Под крышей тело чувствует климат глубины: годовую среднюю клетки плюс тепло недр и тел, тем сильнее, чем больше блоков над ним (`CaveClimate`, `GeoGrad`, `CaveDepthK`, `TmeanTau`; считается по столбу, без объёма полости). Элементы распределены по глубине: смещение каждого из seed, хотя бы один (самый богатый энергией распадов) глубинный, жилы и выбросы вулканов (`GeoProfile`, `DepthScale`, `DepthMid`, `DeepElementMin`, `VeinThreshold`, `VeinGain`). Все детали и направления оптимизации перечислены в [docs/SIMULATION.md](docs/SIMULATION.md).
