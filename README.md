# Primordium

Процедурная симуляция искусственной жизни на **Godot 4.3 C#**. Seed задаёт искусственные элементы, молекулы и геологические условия. Существа исполняют случайные геномы; белки, реакции, питание, движение и размножение получают смысл через отбор. Готовых классов «растение», «хищник», «песок» или «глина» нет.

Описание реализации и её границ: [модель симуляции](docs/SIMULATION.md). История работы: [журнал изменений](docs/CHANGELOG.md). Правила для следующих разработчиков: [AGENTS.md](AGENTS.md).

## Запуск и проверка

Открыть `project.godot` в Godot 4.3 mono. Сборка:

```sh
dotnet build --no-restore -p:UseSharedCompilation=false
```

Безголовое ядро, без Godot:

```sh
dotnet run -c Release --project tools/bench -- --self-test
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 10000 --every 1000 --audit
```

Одиночный долгий прогон быстрее с серверным сборщиком мусора: `DOTNET_gcServer=1 dotnet run -c Release --project tools/bench -- ...` (траектория та же, памяти больше). В батчах и в игре его не включать: много процессов × крупная куча, в игре — паузы до 100+ мс. Динамическая PGO включена в обоих проектах (`TieredPGO`).

Законы мира, сохранения и свои существа в bench:

```sh
dotnet run -c Release --project tools/bench -- --list-params                     # все законы: группа, значение, диапазон
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --set FaceWork=6 --param-at 3000:Gravity=0.0016
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --save /tmp/w.sav
dotnet run -c Release --project tools/bench -- --load /tmp/w.sav --ticks 2000   # продолжает с того же тика, тот же хеш
```

Законы задаются одинаково для одиночного прогона, серии (`--batch`) и длинного теста (`ParamHook`, через `ParamRegistry`): `--preset путь.json` — набор законов (`ParamPreset`; не названные в нём — по умолчанию), `--set Имя=значение` — закон до создания мира (`--param` — то же самое; после `--load` — поверх законов сохранения), `--param-at ТИК:Имя=значение` — смена закона во время прогона (`World.SetParam`, попадает в журнал законов). Имена — из `--list-params`, регистр не важен; значение обрезается по диапазону закона, прогон печатает, что установлено. Неизвестное имя — ошибка до старта. `--save` пишет мир в конце прогона, `--load` продолжает сохранённый (вместе с балансом энергии). `--self-test-cave` — только тест климата пещер, `--self-test-geochem` — только тест геохимии. `--self-test-sun` — только тест неба (длина дня, приток фотонов, затенение, затмения, вспышки). `--sun [--seeds 1,2,3]` — таблица длины дня по широтам и сезонам, климат широты старым и новым законом, расписание затмений и вспышек первых 12 000 тиков и годовой приток фотонов мира без жизни против прежнего закона. `--geochem [--seeds 1-4] [--ticks 3000]` — химия мира, состав породы на 0/3/10/30/60 уровнях под верхом столба, выбросы вулканов, что держат тела и на что нацелены их белки. `--resources [--seeds 1-4] [--ticks 6000] [--from 3000]` — куда идут газ воздуха и рыхлое вещество по регионам 32×32: запасы, поглощение, выброс и смерть, диффузия, распад и дождь, за сколько суток регион опустел бы, что держат тела и сколько они вообще поглощают (`World.ResProbe`, только наблюдение). `--self-test-resources` — только тест ресурсов. `--self-test-wear` — только тест фотоповреждения и износа вещества тела (сохранение атомов, потоки баланса, «запечатанное» тело без поглощения). `--invade [--seeds 1-6] [--at 2000] [--ticks 8000] [--count 5] [--spots 6] [--design Крот]` — посадить пример (вещество и энергия извне) и следить за его линией: число тел, глубина, крыша, доля глубинного элемента. `--self-test-infra` — только тесты законов (в том числе смена законов посреди прогона под балансами), сохранения, `lifeSeed`, текста генома, своих существ и хроники. `--chronicle` печатает хронику мира по мере событий (`!` — важное); `--log` добавляет в CSV число событий, важных и окаменелостей, а также все дорожки хода эволюции (`EvolutionHistory.Names`: `adaptive`, `novelty`, `code_used`, `niches`, `mrca_age`, `pair_dist`, …, `progress_index`) и память наблюдателя `evo_mb`; на каждой отметке печатается строка `progress:`. Те же колонки попадают в `runs.csv` и `summary.csv` серий и в `--compare`. `--self-test-evolution` — только тест хода эволюции.

`--audit` считает элементы в породе, телах, белках, дробном поглощении, атмосфере, осадках и захоронениях. Отдельно вычитает учтённый приток из недр и от руки. Рядом печатает энергетический баланс: запас по резервуарам, потоки (свет, удары, вулканы, рука, свои существа, `EnergyK`, тепло затрат, распада, смерти, давления) и дрейф `запас − (входы − выходы)` с допуском (см. «Балансы» в docs/SIMULATION.md). На каждой отметке печатается строка `evo:` — метрики эволюции (разнообразие геномов и линий, смена линий, белки, питание, новизна); `--log` пишет их колонками. `--pop N`, `--noabio`, `--probe` и `--genome ...` помогают воспроизводить эксперименты. Профиль выводит время неба, диффузии, химии/климата, опор (по частям) и агентов (работа квадратов и самый медленный квадрат); `--ops` добавляет время по командам VM. Мир детерминирован: тот же seed даёт ту же траекторию, поэтому оптимизации удобно сравнивать до/после.

Решения о законах принимать по сериям, а не по одному прогону: один сид в разных версиях давал от 36 тыс. до 116 существ.

```sh
# 16 сидов × 3 повтора по 6000 тиков, отметки каждые 1000, 3 процесса одновременно
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --every 1000 --jobs 3 --out runs/base
dotnet run -c Release --project tools/bench -- --batch --seeds 1-16 --reps 3 --ticks 6000 --every 1000 --out runs/try --set CostBase=0.02
dotnet run -c Release --project tools/bench -- --compare runs/base/runs.csv runs/try/runs.csv
dotnet run -c Release --project tools/bench -- --long-test            # сиды 1,2,3 по 20 000 тиков: атомы, энергия, детерминизм, обвалы
```

- `--batch`: `--seeds 1-16` (или `1,4,7-9`), `--reps R` (повтор 0 — мир сида, r > 0 — тот же мир с другой «жизнью»: `WorldSettings.LifeSeed = r` меняет только первые тела и случайные потоки существ), `--ticks`, `--every`, `--pop`, `--noabio`, `--tile`, `--audit` (энергия и атомы в каждой строке), `--jobs J` (процессов одновременно; по умолчанию ядра/3), `--out каталог`, пороги `--extinct N` (≤ N тел в конце; 10) и `--boom N` (> N на любой отметке; 20000), законы `--preset`/`--set`/`--param-at` (каждый прогон получает их как есть; колонка `params` в `runs.csv`). Каждый прогон — отдельный процесс. Результат: `runs.csv`, `summary.csv`, журналы прогонов в `runs/` и таблица: численность на отметках, вымирания, бумы, температура, метрики эволюции, мс/тик.
- `--compare a.csv b.csv`: медианы и квартили, разность медиан с бутстреп-интервалом, Манн — Уитни, знаковый тест по сидам, Фишер для вымираний и бумов; флаг `* differs` / `~ noise`.
- `--life N` — одиночный прогон с другим `lifeSeed`.
- `--long-test [--seeds 1,2,3] [--ticks 20000] [--every 2000]` — длинная регрессия: баланс атомов и энергии на каждой отметке, у первого сида параллельный двойник с тем же хешем состояния, и проверка, что обвалы, дробление и захоронения, осадки и реакции давления действительно происходили. `--self-test` остаётся быстрым.

Godot принимает `--abio` и `--strikes` (самозарождение и удары с орбиты в новом мире **по умолчанию выключены**: жизнь запускает игрок — N, свои существа — или клавиши A и ⇧X), `--seed N`, `--warm N`, `--slice ROW`, `--zoom Z`, `--shot /path/image.png`, а для снимков кисти `--tool 1..5 --paint K` (K мазков в центре экрана перед снимком). Окна для снимков: `--open laws,newworld,saves,creator` (через запятую; `newworld:more` — с раскрытым «Дополнительно», `creator:looks` и `creator:help` — вкладки конструктора; `chronicle`, `chronicle:fossils` — хроника и список окаменелостей; `evolution` — ход эволюции; `fossil`, `fossil:bio`, `fossil:ancestry` — самая важная окаменелость). `--seltracked` выбирает живое существо с самой длинной биографией, `--tab bio` открывает в карточке вкладку «Биография». `--load путь.sav` загружает сохранение вместо нового мира, `--selcave` выбирает тело под самой толстой крышей и делает разрез через него. `--lookeclipse` подводит камеру к тени спутника, если идёт затмение, `--looksun` — к дневной стороне (снимки неба). `--open none` — без окон (и без восстановления открытых из `ui.json`). `--uitest` — сценарий проверки окон: смена закона, быстрое сохранение, посадка всех примеров (извне и из местного вещества), быстрая загрузка; итоги и всплывающие сообщения печатаются строками `uitest:` и `notice:`. После прогрева снимок делается через несколько кадров. Пока продолжаете менять код, запускайте долгие прогоны из отдельной копии сборки, чтобы не перезаписывать исполняемый DLL.

Мир шагает в отдельном потоке (`src/SimRunner.cs`), кадр его не ждёт: вид рисует последний опубликованный снимок существ, а действия руки, N, X, A, пауза, шаг, скорость и промотка уходят командами и применяются между тиками. Скорость `×N` — цель N тиков за 1/60 с (как прежние «тики за кадр» при 60 кадрах/с), если мир успевает.

Замер производительности: `--perf N` печатает каждые N кадров строку `PERF` (кадр, тики/с и мс на тик, этапы `World.Prof`, шаги вида, HUD, загрузки на GPU, примитивы и вызовы отрисовки), `--perfquit K` выходит после K строк, `--pauseafter K` ставит паузу после K строк, `--perfshow` сразу открывает оверлей F3. Ещё `--tpf N` (начальная скорость), `--overlay K` (карта поверхности), `--viewthreads N` (потоки заполнения вида, 0 — только главный). Пример:

```sh
Godot --path . -- --seed 2 --warm 10000 --perf 120 --pauseafter 3 --perfquit 6
```

## Управление

| Клавиша / действие | Результат |
|---|---|
| Space / `.` | Пауза / один тик |
| T / ⇧T | Промотка на указанное число суток / сразу на 10 суток; T или Esc останавливает |
| `+` / `−` | Скорость симуляции (цель тиков в секунду; мир идёт в своём потоке) |
| ЛКМ с перетаскиванием, WASD, два пальца | Сдвиг карты |
| ПКМ с перетаскиванием, Q / E | Поворот |
| Колесо / щипок / G | Зум / показать всю карту |
| Наведение / клик | Карточка / выбор существа |
| K / F / Esc | Подсветка родни / слежение / снять выбор |
| H / B / O | Легенда / рекорды / старейшее существо |
| V | Цвет существ: родство, питание, линия, энергия, белки |
| M / ⇧M | Карты поверхности, температуры, **мощности солнца** у поверхности, остатков, жизни, смертей, тепла, **нагрузки**, **решётки**, **температуры на глубине** (сверху — средняя за год, в разрезе C — что чувствует тело на каждом уровне), **глубинного элемента** (доля глубинного элемента в атомах блока: сверху — верхний блок, в разрезе C — по уровням, жилы светлее), **запаса еды и газа** (рыхлое на земле — зелёный → жёлтый, газ воздуха — синий, чёрное — выедено), **прозрачности атмосферы**, **длины дня**, **дозы солнечной вспышки**, молекул |
| L | Освещение солнцем |
| F3 | Оверлей производительности: кадр, поток мира, этапы вида |
| C, `[` / `]` | Разрез и его положение; видны полости, полы и своды |
| N / A | Попытаться собрать группу существ из местного вещества / переключить абиогенез (в новом мире выключен) |
| X / ⇧X | Удар из космоса / автоматические удары (в новом мире выключены; мутагенное давление по умолчанию — солнечные вспышки, закон `Flares`) |
| R / ⇧R / P | Новый seed / тот же seed заново / снимок на рабочий стол |
| 1 / 2 / 3 / 4 | Кисть: насыпать случайный материал (каждый мазок — новый) / залить водой / убить всех в круге / копнуть. ЛКМ рисует, `[` `]` — радиус (1–24), та же цифра, 0 или Esc убирает кисть |
| 5 | Кисть «посадить»: клик сажает дизайн из конструктора в клетку; `[` `]` — радиус разброса, если сажается несколько |
| F2 / F4 | Окна «Законы мира» / «Новый мир» |
| F5 / F9 | Быстрое сохранение / быстрая загрузка (`quick.sav`) |
| F6 / F7 | Окно «Сохранения» / конструктор существ |
| F8 | Хроника мира: лента событий и окаменелости |
| F10 | Ход эволюции: новизна против нейтральной тени, сложность, экология, темп, филогения |
| Esc | Закрыть верхнее окно (если окон нет — как раньше: промотка, кисть, выбор) |

## Законы мира, сохранения, свои существа

Всё это доступно в окнах игры (кнопки под верхней строкой и клавиши F2–F10). Окна перетаскиваются за заголовок, меняют размер за правый нижний угол и запоминают положение и открытость в `user://ui.json` (на macOS — `~/Library/Application Support/Godot/app_userdata/Primordium`). Пока курсор над окном, карта не двигается и кисть не рисует; пока печатаете в поле, клавиши не управляют игрой. Итоги команд (сохранено, посажено, закон изменён, ошибки) всплывают сообщениями слева внизу.

- **Законы мира (F2).** Группы реестра слева, поиск по имени и описанию. У каждого закона ползунок, поле числа, диапазон, описание (подробности — во всплывающей подсказке), отметка «изменён» и сброс. Ползунок применяется при отпускании (сила тяжести и прочность пересчитывают опору всей карты), число — по Enter. Законы, которые читаются только при создании мира, заблокированы с пометкой «только для нового мира». Внизу — «всё по умолчанию» и наборы законов: сохранить текущие (в `user://presets/`, только отличия от умолчаний), применить, удалить.
- **Новый мир (F4).** Seed (и случайный), начальное население (0 — пустой мир), самозарождение, удары с орбиты, солнечные вспышки и затмения (законы `Flares`, `Eclipses`), законы: текущие, по умолчанию или набор. «Дополнительно» раскрывает все законы нового мира, включая читаемые только при создании. Мир строится в потоке симуляции, игра при этом не замирает. R и ⇧R работают как раньше.
- **Сохранения (F6).** Слоты в `user://saves/`: миниатюра карты в момент сохранения (`имя.png` рядом с `имя.sav`), сутки, тик, население, seed, дата, заметка. Сохранить в новый слот, перезаписать, удалить (второй клик подтверждает), загрузить. Автосохранение каждые N минут (0 — выключено, по умолчанию 10) по кругу в K файлов `autosave_N.sav`. F5 и F9 — быстрые сохранение и загрузка.
- **Конструктор (F7).** Библиотека дизайнов `user://creatures/` (при первом запуске туда кладутся примеры, «Вернуть примеры» восстанавливает удалённые): новый, копия, сохранить, удалить, «взять у выбранного» — геном, тело и облик выбранного на карте существа. Геном пишется текстом с подсветкой команд; строки с ошибками подсвечиваются, под редактором — ошибки или длина, число команд и генов белка. Вкладка «Тело и посадка»: молекулы тела (номер вида этого мира, `gas`, `any`) и их число, энергия, откуда вещество и энергия (местные или принесённые извне — с объяснением учёта), сколько сажать, и сколько нужного рыхлого вещества и энергии местных распадов есть у курсора. «Облик» — свой цвет и форма или облик из генома, портрет по геному. «Справка» — все команды ВМ из её таблицы с кратким описанием. Кисть 5 сажает дизайн по клику. Посаженные отмечены в карточке существа: «от игрока: посажен из дизайна …» или «потомок дизайна …».
- **Хроника (F8).** Лента событий мира: первые белки и реакции, открытия пород, смены питания линий, рекорды глубины и прочие рекорды, первый пловец, житель пещер, хищник, паразит, видообразование, вымирание, новый доминант, удары с орбиты, солнечные вспышки (облучено, мутаций, погибло), затмения (полоса тени) и вулканы, действия игрока (посадка, законы, сохранения). Фильтры: типы (с числом событий каждого), линия, время, «только важное». Клик по событию: живое существо — камера летит к нему и выбирает его, мёртвое — открывается его окаменелость, иначе камера летит к месту. Вкладка «Окаменелости» — все сохранённые тела. Важные события — цветные чёрточки над графиком населения (наведение — подпись).
- **Ход эволюции (F10).** Пять дорожек на общей шкале времени: новизна (компоненты, чья активность выше нейтральной тени: мир, контрольная тень и их разность), сложность (используемый код, белков и реакций на тело, масса), экология (ниши, разнообразие питания, крупные линии, доли под землёй и в воде), темп (смены доминанта, видообразования и вымирания на 10 тыс. тиков, дрейф самого частого генома), филогения (возраст MRCA крупнейшей линии, среднее попарное расстояние, живые генотипы, длина линии). Поверх — важные события хроники; наведение показывает значения и события в точке; окно времени; CSV в `user://evolution/`. Сверху — сводная **подсказка** «идёт / стагнирует / откат» (медиана трендов четырёх дорожек за `ProgressWindow`): подсказка, а не вывод — смотреть надо на дорожки.
- **Окаменелость.** Когда жило, отчего умерло, почему сохранено, состав тела, белки, геном текстом, биография, цепочка отслеживаемых предков до основателя (клик — к живому или к окаменелости). «Воскресить» открывает её в конструкторе как дизайн — дальше кисть 5.
- **Биография** — вкладка в карточке выбранного существа: почему ведётся, родитель, предки и живые дети (ссылки), график энергии и массы, лента жизни (рождение, первые белки и реакции, уход под землю и выход, убийства, кражи, дары, облучение, рекорды, потомки, события, смерть). Выбранное существо отслеживается с момента выбора; основатели линий и посаженные — с рождения, участники событий — с события.

Ядро (команды — в `SimRunner`):
- **Законы мира** — 161 настраиваемая величина `P` (цены, скорости, пороги, прочность, климат, климат пещер, геохимия, ресурсы, вода, небо: инсоляция, прозрачность, затенение, затмения, вспышки; износ вещества тела: фотоповреждение и износ). `ParamRegistry` знает о каждой группу, описание, диапазон, шаг и меняется ли она на ходу. Меняются между тиками (`SimRunner.SetParam`), записываются в `World.ParamLog`: траектория = seed + история законов. Наборы законов — JSON (`ParamPreset`).
- **Новый мир** — `WorldSettings`: seed, начальное население, самозарождение, удары, набор законов.
- **Сохранение** — весь мир в один файл (Brotli): после загрузки он идёт ровно так же, как шёл бы исходный. Есть автосохранение по кругу.
- **Свои существа** — геном пишется текстом (по команде в строке, `GenomeAsm`), любое живое существо можно разобрать в текст. `CreatureDesign` — геном, состав тела и энергия, хранится в JSON. Сажать можно из местного вещества и энергии местных реакций или принеся их извне — тогда они учитываются в `HandInput`/`HandEnergy`. Даром ничего не появляется. Примеры: «Листок», «Крот», «Пловец».
- **Хроника** — `World.Chronicle`: события, окаменелости, родословная отслеживаемых, биографии (`Agent.Bio`). Только наблюдение: хеш мира тот же, что без неё. В сохранении. Подробно — «Хроника» в docs/SIMULATION.md.
- **Ход эволюции** — `World.Shadow` (нейтральные тени Бедау и активность компонентов), `World.Phylo` (родословная всех живых по генотипам, с обрезкой), `World.Progress` (дорожки раз в `ProgressEvery` тиков). Только наблюдение: хеш мира тот же. В сохранении (версия 4). Подробно — «Ход эволюции» в docs/SIMULATION.md.

Подробности — в [docs/SIMULATION.md](docs/SIMULATION.md).

## Материя и геология

В каждом мире четыре искусственных элемента со своими массами, сродством и валентностью. Из них генерируются 16 формул, каждая в основном и возбуждённом состоянии: всего 32 вида молекул. Звёздочка в имени означает возбуждение, а не новый элемент. Молекула имеет вектор состава, массу, энергию, связность и склонность к упаковке.

Соединение допустимо только при наличии продукта с суммой исходных составов. Распад возвращает составляющие; возбуждённый одиночный элемент может расслабиться в своё основное состояние. Свет поднимает энергию того же состава. Недопустимая реакция ничего не создаёт.

Планета — цилиндр 256×160 клеток, до 192 блоков по высоте: земля в среднем ~72 блока толщиной (кора `World.Crust` = 60 под самыми низкими местами), рельеф от долин до гор ~25 блоков, над ним ~100 блоков воздуха. Начальные пласты выбираются по свойствам молекул, глубине и пространственно связанным случайным полям. У каждого блока есть оставшийся состав и порядок решётки. Постройки и осадки хранят именно внесённые молекулы, включая смеси. Два нижних уровня — непроходимая граница модели недр.

## Опора, подкоп и обвал

`mine` добывает под ногами; `gnaw` — стену на высоте тела или доступный соседний пол. Когда блок исчерпан, остаётся пустота. Верхняя порода может удержаться через соседние блоки. Существа могут зайти в полость, копать дальше, родить там потомство и добывать лежащие на её полу останки. Под непрозрачным потолком нет поверхностных фотонов.

Нагрузка зависит от массы породы, захороненного вещества и массы стоящих на ней существ. В массу тела входят также дробное поглощение и материальный субстрат белков. Подъём тяжёлого тела дороже; падение тяжелее.

Монолит лучше передаёт нагрузку. Разные составы слабо сцепляются на границе; смесь ослаблена и внутри блока. Частичная добыча уменьшает несущую площадь. Опора прослеживается до заземлённой породы: висящий замкнутый пласт не может поддерживать сам себя. Перегруженная опора дробится, неподдерживаемые блоки падают, разрушая следующие опоры каскадом.

Существо в пути падающего блока погибает от обвала. Его молекулы, частично поглощённое вещество и белки остаются **на глубине столкновения**. Давление и температура меняют порядок этого захороненного агрегата; допустимые реакции соединяют его молекулы без изменения элементов. Перестройка влияет на механическую связность. Готового правила «труп → уголь» нет.

Карта нагрузки показывает отношение давления к прочности на сжатие; красные участки близки к перегрузке. Это не полная карта боковых напряжений. Карта решётки показывает порядок верхнего блока. В инспекторе существа есть высота, давление и прочность опоры.

## Круговорот

- Поглощение переносит вещество среды в тело, выброс возвращает его на доступную высоту.
- Белок сохраняет молекулу-субстрат. При износе и повреждении она возвращается в тело или выпадает наружу.
- Смерть возвращает состав тела; оставшаяся пригодная энергия рассеивается теплом.
- Вещество тела изнашивается (законы `PhotoDamage` и `WearK`, группа «Износ», по умолчанию выключены): пойманный фотон может разрушить возбуждённую молекулу вместо запаса энергии, а каждая молекула тела — потерять связь с телом от тепла. Молекула уходит на пол клетки своим экзотермическим распадом (энергия — теплом, поток `body decay`) или целой; чем прочнее её связность (и плотнее матрица тела для фотоповреждения), тем реже. Без этих законов свет на своих же молекулах — вечная батарея (`D1 → D1* → D1`), и тело может не поглощать вещества всю жизнь.
- Осадки собираются из фактического запаса молекул, без пересчёта энергии в «гумус».
- Выветривание и разрушение освобождают вещество блока, сохраняя его состав.
- Газ распространяется над поверхностью (скорость — закон `GasDiffK`, по умолчанию 1); дождь может адсорбировать часть существующих атмосферных молекул на породе. Они снова доступны для поглощения на открытом полу. Под крышей газ воздуха по умолчанию недоступен; закон `CaveGasK` даёт телу под крышей долю `e^(−крыша/CaveGasK)` газа своего столба (из того же запаса, что пьёт поверхность).
- Вулкан добавляет вещество из внешнего для расчётной коры резервуара; этот приток записывается отдельно.
- Абиогенез, включая N и диагностический `probe`, использует местные молекулы и энергию разрешённых реакций. Если ресурсов нет, создание не удаётся.

Материя и энергия учитываются раздельно: тепло не превращается в новые элементы. Питание использует разницу энергий состояний; свет пополняет химическую энергию. Затраты действий и жизни рассеиваются теплом. Температура и вода остаются упрощёнными климатическими полями, а не атомистической термодинамикой.

## Жизнь и геном

Геном — стековая машина: обычно 8 тактов за тик, стек и память по 16 ячеек, вызовы и переходы. Младшие 6 бит байта выбирают команду; старшие 2 — вариант или небольшое число. Мутации меняют, вставляют, удаляют и дублируют код. Полезные участки получают частичную защиту при наследовании.

`enzyme` читает три следующих байта: тип катализа, целевые молекулы, температурный оптимум и эффективность. Возможны соединение, распад/релаксация, захват света и мотор. Ген не выдаёт готовую цепочку питания: код должен обеспечить её входы и использовать выходы. Белки изнашиваются, тело требует энергии, жара и мороз повреждают его. Рост по массе позволяет телу занимать несколько клеток; родственные формы наследуют внешний вид с дрейфом.

| Группа | Команды |
|---|---|
| Стек, числа | `push lit dup drop swap over rot add sub mul div mod neg inc dec lt eq rand` |
| Управление, память | `label jmp jz jnz call ret skipz yield load store` |
| Состояние тела | `energy age have mass temp btemp gene glen` |
| Мир | `sense sensed smell light photons uv look ground` |
| Внимание и общение | `pick count feel kin ngene listen emit hurt` |
| Белки и химия | `enzyme bind split photo digest` |
| Мембрана и движение | `intake drink expel push swim` |
| Жизнь и взаимодействия | `divide mate attack take give share link inject cut` |
| Порода | `mine gnaw dig pile grow` |

`push` толкает тело мотором в одну из 4 сторон; `swim` (второе значение `nop`) — гребок вверх или вниз, только в воде. В воде тело без газа тонет и ходит по дну (вода легче любой молекулы); газ в теле — пузырь, поэтому `intake`/`expel` газа выбирают глубину. У поверхности свет и воздух, у дна останки; каждый гребок тем дороже, чем глубже (подробно — «Вода» в docs/SIMULATION.md). `dig` переносит блок целиком; `pile` собирает блок из одинаковых твёрдых молекул; `grow` выделяет агрегат из четырёх имеющихся молекул тела. Древесина не является особым материалом. Связи колонии требуют взаимного согласия. Способности и устойчивые цепочки возникают через случайный код и отбор.

## Текущий масштаб модели

Это конечная искусственная химия и приближённая механика вокселей. Решётка представлена составом, связностью и параметром порядка; явных координат атомов и расчёта упругих деформаций нет. Опорный граф выбирает один сильнейший путь на блок и может консервативно разрушать свод, который выдержал бы более точный расчёт. Вода и атмосфера пока поверхностные (в воде есть плавучесть, глубина и свет по глубине, но нет течений). Под крышей тело чувствует климат глубины: годовую среднюю клетки плюс тепло недр и тел, тем сильнее, чем больше блоков над ним (`CaveClimate`, `GeoGrad`, `CaveDepthK`, `TmeanTau`; считается по столбу, без объёма полости). Элементы распределены по глубине: смещение каждого из seed, хотя бы один (самый богатый энергией распадов) глубинный, жилы и выбросы вулканов (`GeoProfile`, `DepthScale`, `DepthMid`, `DeepElementMin`, `VeinThreshold`, `VeinGain`). Все детали и направления оптимизации перечислены в [docs/SIMULATION.md](docs/SIMULATION.md).
