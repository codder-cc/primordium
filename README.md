# Primordium

Процедурная симуляция искусственной жизни на **Godot 4.3 C#**. Seed задаёт искусственные элементы, молекулы и геологические условия. Существа исполняют случайные геномы; белки, реакции, питание, движение и размножение получают смысл через отбор. Готовых классов «растение», «хищник», «песок» или «глина» нет.

Описание реализации и её границ: [модель симуляции](docs/SIMULATION.md). История работы: [журнал изменений](docs/CHANGELOG.md). Правила для следующих разработчиков: [AGENTS.md](AGENTS.md).

## Запуск и проверка

Открыть `project.godot` в Godot 4.3 mono. Сборка:

```sh
dotnet build --no-restore -p:UseSharedCompilation=false
```

Безголовое ядро, без Godot:

```sh
dotnet run -c Release --project tools/bench -- --self-test
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 10000 --every 1000 --audit
```

Одиночный долгий прогон быстрее с серверным сборщиком мусора: `DOTNET_gcServer=1 dotnet run -c Release --project tools/bench -- ...` (траектория та же, памяти больше). В батчах и в игре его не включать: много процессов × крупная куча, в игре — паузы до 100+ мс. Динамическая PGO включена в обоих проектах (`TieredPGO`).

Законы мира, сохранения и свои существа в bench:

```sh
dotnet run -c Release --project tools/bench -- --list-params                     # все законы: группа, значение, диапазон
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --param FaceWork=6 --param-at 3000:Gravity=0.0016
dotnet run -c Release --project tools/bench -- --seed 1 --ticks 5000 --save /tmp/w.sav
dotnet run -c Release --project tools/bench -- --load /tmp/w.sav --ticks 2000   # продолжает с того же тика, тот же хеш
```

`--preset путь.json` — набор законов (`ParamPreset`), `--param Имя=значение` — закон до создания мира (после `--load` — поверх законов сохранения), `--param-at ТИК:Имя=значение` — смена закона во время прогона. `--save` пишет мир в конце прогона, `--load` продолжает сохранённый. `--self-test-infra` — только тесты законов, сохранения, текста генома и своих существ.

`--audit` считает элементы в породе, телах, белках, дробном поглощении, атмосфере, осадках и захоронениях. Отдельно вычитает учтённый приток из недр. `--pop N`, `--noabio`, `--probe` и `--genome ...` помогают воспроизводить эксперименты. Профиль выводит время неба, диффузии, химии/климата, опор (по частям) и агентов (работа квадратов и самый медленный квадрат); `--ops` добавляет время по командам VM. Мир детерминирован: тот же seed даёт ту же траекторию, поэтому оптимизации удобно сравнивать до/после.

Godot принимает `--abio` и `--strikes` (самозарождение и удары с орбиты в новом мире **по умолчанию выключены**: жизнь запускает игрок — N, свои существа — или клавиши A и ⇧X), `--seed N`, `--warm N`, `--slice ROW`, `--zoom Z`, `--shot /path/image.png`, а для снимков кисти `--tool 1..5 --paint K` (K мазков в центре экрана перед снимком). Окна для снимков: `--open laws,newworld,saves,creator` (через запятую; `newworld:more` — с раскрытым «Дополнительно», `creator:looks` и `creator:help` — вкладки конструктора). `--uitest` — сценарий проверки окон: смена закона, быстрое сохранение, посадка всех примеров (извне и из местного вещества), быстрая загрузка; итоги и всплывающие сообщения печатаются строками `uitest:` и `notice:`. После прогрева снимок делается через несколько кадров. Пока продолжаете менять код, запускайте долгие прогоны из отдельной копии сборки, чтобы не перезаписывать исполняемый DLL.

Мир шагает в отдельном потоке (`src/SimRunner.cs`), кадр его не ждёт: вид рисует последний опубликованный снимок существ, а действия руки, N, X, A, пауза, шаг, скорость и промотка уходят командами и применяются между тиками. Скорость `×N` — цель N тиков за 1/60 с (как прежние «тики за кадр» при 60 кадрах/с), если мир успевает.

Замер производительности: `--perf N` печатает каждые N кадров строку `PERF` (кадр, тики/с и мс на тик, этапы `World.Prof`, шаги вида, HUD, загрузки на GPU, примитивы и вызовы отрисовки), `--perfquit K` выходит после K строк, `--pauseafter K` ставит паузу после K строк, `--perfshow` сразу открывает оверлей F3. Ещё `--tpf N` (начальная скорость), `--overlay K` (карта поверхности), `--viewthreads N` (потоки заполнения вида, 0 — только главный). Пример:

```sh
Godot --path . -- --seed 2 --warm 10000 --perf 120 --pauseafter 3 --perfquit 6
```

## Законы мира, сохранения, свои существа

Всё это доступно в окнах игры (кнопки под верхней строкой и клавиши F2–F9). Окна перетаскиваются за заголовок, меняют размер за правый нижний угол и запоминают положение и открытость в `user://ui.json` (на macOS — `~/Library/Application Support/Godot/app_userdata/Primordium`). Пока курсор над окном, карта не двигается и кисть не рисует; пока печатаете в поле, клавиши не управляют игрой. Итоги команд (сохранено, посажено, закон изменён, ошибки) всплывают сообщениями слева внизу.

- **Законы мира (F2).** Группы реестра слева, поиск по имени и описанию. У каждого закона ползунок, поле числа, диапазон, описание (подробности — во всплывающей подсказке), отметка «изменён» и сброс. Ползунок применяется при отпускании (сила тяжести и прочность пересчитывают опору всей карты), число — по Enter. Законы, которые читаются только при создании мира, заблокированы с пометкой «только для нового мира». Внизу — «всё по умолчанию» и наборы законов: сохранить текущие (в `user://presets/`, только отличия от умолчаний), применить, удалить.
- **Новый мир (F4).** Seed (и случайный), начальное население (0 — пустой мир), самозарождение, удары с орбиты, законы: текущие, по умолчанию или набор. «Дополнительно» раскрывает все законы нового мира, включая читаемые только при создании. Мир строится в потоке симуляции, игра при этом не замирает. R и ⇧R работают как раньше.
- **Сохранения (F6).** Слоты в `user://saves/`: миниатюра карты в момент сохранения (`имя.png` рядом с `имя.sav`), сутки, тик, население, seed, дата, заметка. Сохранить в новый слот, перезаписать, удалить (второй клик подтверждает), загрузить. Автосохранение каждые N минут (0 — выключено, по умолчанию 10) по кругу в K файлов `autosave_N.sav`. F5 и F9 — быстрые сохранение и загрузка.
- **Конструктор (F7).** Библиотека дизайнов `user://creatures/` (при первом запуске туда кладутся примеры, «Вернуть примеры» восстанавливает удалённые): новый, копия, сохранить, удалить, «взять у выбранного» — геном, тело и облик выбранного на карте существа. Геном пишется текстом с подсветкой команд; строки с ошибками подсвечиваются, под редактором — ошибки или длина, число команд и генов белка. Вкладка «Тело и посадка»: молекулы тела (номер вида этого мира, `gas`, `any`) и их число, энергия, откуда вещество и энергия (местные или принесённые извне — с объяснением учёта), сколько сажать, и сколько нужного рыхлого вещества и энергии местных распадов есть у курсора. «Облик» — свой цвет и форма или облик из генома, портрет по геному. «Справка» — все команды ВМ из её таблицы с кратким описанием. Кисть 5 сажает дизайн по клику. Посаженные отмечены в карточке существа: «от игрока: посажен из дизайна …» или «потомок дизайна …».

Ядро (команды — в `SimRunner`):
- **Законы мира** — 105 настраиваемых величин `P` (цены, скорости, пороги, прочность, климат, вода). `ParamRegistry` знает о каждой группу, описание, диапазон, шаг и меняется ли она на ходу. Меняются между тиками (`SimRunner.SetParam`), записываются в `World.ParamLog`: траектория = seed + история законов. Наборы законов — JSON (`ParamPreset`).
- **Новый мир** — `WorldSettings`: seed, начальное население, самозарождение, удары, набор законов.
- **Сохранение** — весь мир в один файл (Brotli): после загрузки он идёт ровно так же, как шёл бы исходный. Есть автосохранение по кругу.
- **Свои существа** — геном пишется текстом (по команде в строке, `GenomeAsm`), любое живое существо можно разобрать в текст. `CreatureDesign` — геном, состав тела и энергия, хранится в JSON. Сажать можно из местного вещества и энергии местных реакций или принеся их извне — тогда они учитываются в `HandInput`/`HandEnergy`. Даром ничего не появляется. Примеры: «Листок», «Крот», «Пловец».

Подробности — в [docs/SIMULATION.md](docs/SIMULATION.md).

## Материя и геология

В каждом мире четыре искусственных элемента со своими массами, сродством и валентностью. Из них генерируются 16 формул, каждая в основном и возбуждённом состоянии: всего 32 вида молекул. Звёздочка в имени означает возбуждение, а не новый элемент. Молекула имеет вектор состава, массу, энергию, связность и склонность к упаковке.

Соединение допустимо только при наличии продукта с суммой исходных составов. Распад возвращает составляющие; возбуждённый одиночный элемент может расслабиться в своё основное состояние. Свет поднимает энергию того же состава. Недопустимая реакция ничего не создаёт.

Планета — цилиндр 256×160 клеток, до 192 блоков по высоте: земля в среднем ~72 блока толщиной (кора `World.Crust` = 60 под самыми низкими местами), рельеф от долин до гор ~25 блоков, над ним ~100 блоков воздуха. Начальные пласты выбираются по свойствам молекул, глубине и пространственно связанным случайным полям. У каждого блока есть оставшийся состав и порядок решётки. Постройки и осадки хранят именно внесённые молекулы, включая смеси. Два нижних уровня — непроходимая граница модели недр.

## Опора, подкоп и обвал

`mine` добывает под ногами; `gnaw` — стену на высоте тела или доступный соседний пол. Когда блок исчерпан, остаётся пустота. Верхняя порода может удержаться через соседние блоки. Существа могут зайти в полость, копать дальше, родить там потомство и добывать лежащие на её полу останки. Под непрозрачным потолком нет поверхностных фотонов.

Нагрузка зависит от массы породы, захороненного вещества и массы стоящих на ней существ. В массу тела входят также дробное поглощение и материальный субстрат белков. Подъём тяжёлого тела дороже; падение тяжелее.

Монолит лучше передаёт нагрузку. Разные составы слабо сцепляются на границе; смесь ослаблена и внутри блока. Частичная добыча уменьшает несущую площадь. Опора прослеживается до заземлённой породы: висящий замкнутый пласт не может поддерживать сам себя. Перегруженная опора дробится, неподдерживаемые блоки падают, разрушая следующие опоры каскадом.

Существо в пути падающего блока погибает от обвала. Его молекулы, частично поглощённое вещество и белки остаются **на глубине столкновения**. Давление и температура меняют порядок этого захороненного агрегата; допустимые реакции соединяют его молекулы без изменения элементов. Перестройка влияет на механическую связность. Готового правила «труп → уголь» нет.

Карта нагрузки показывает отношение давления к прочности на сжатие; красные участки близки к перегрузке. Это не полная карта боковых напряжений. Карта решётки показывает порядок верхнего блока. В инспекторе существа есть высота, давление и прочность опоры.

## Круговорот

- Поглощение переносит вещество среды в тело, выброс возвращает его на доступную высоту.
- Белок сохраняет молекулу-субстрат. При износе и повреждении она возвращается в тело или выпадает наружу.
- Смерть возвращает состав тела; оставшаяся пригодная энергия рассеивается теплом.
- Осадки собираются из фактического запаса молекул, без пересчёта энергии в «гумус».
- Выветривание и разрушение освобождают вещество блока, сохраняя его состав.
- Газ распространяется над поверхностью; дождь может адсорбировать часть существующих атмосферных молекул на породе. Они снова доступны для поглощения на открытом полу.
- Вулкан добавляет вещество из внешнего для расчётной коры резервуара; этот приток записывается отдельно.
- Абиогенез, включая N и диагностический `probe`, использует местные молекулы и энергию разрешённых реакций. Если ресурсов нет, создание не удаётся.

Материя и энергия учитываются раздельно: тепло не превращается в новые элементы. Питание использует разницу энергий состояний; свет пополняет химическую энергию. Затраты действий и жизни рассеиваются теплом. Температура и вода остаются упрощёнными климатическими полями, а не атомистической термодинамикой.

## Жизнь и геном

Геном — стековая машина: обычно 8 тактов за тик, стек и память по 16 ячеек, вызовы и переходы. Младшие 6 бит байта выбирают команду; старшие 2 — вариант или небольшое число. Мутации меняют, вставляют, удаляют и дублируют код. Полезные участки получают частичную защиту при наследовании.

`enzyme` читает три следующих байта: тип катализа, целевые молекулы, температурный оптимум и эффективность. Возможны соединение, распад/релаксация, захват света и мотор. Ген не выдаёт готовую цепочку питания: код должен обеспечить её входы и использовать выходы. Белки изнашиваются, тело требует энергии, жара и мороз повреждают его. Рост по массе позволяет телу занимать несколько клеток; родственные формы наследуют внешний вид с дрейфом.

| Группа | Команды |
|---|---|
| Стек, числа | `push lit dup drop swap over rot add sub mul div mod neg inc dec lt eq rand` |
| Управление, память | `label jmp jz jnz call ret skipz yield load store` |
| Состояние тела | `energy age have mass temp btemp gene glen` |
| Мир | `sense sensed smell light photons look ground` |
| Внимание и общение | `pick count feel kin ngene listen emit hurt` |
| Белки и химия | `enzyme bind split photo digest` |
| Мембрана и движение | `intake drink expel push swim` |
| Жизнь и взаимодействия | `divide mate attack take give share link inject cut` |
| Порода | `mine gnaw dig pile grow` |

`push` толкает тело мотором в одну из 4 сторон; `swim` (второе значение `nop`) — гребок вверх или вниз, только в воде. В воде тело без газа тонет и ходит по дну (вода легче любой молекулы); газ в теле — пузырь, поэтому `intake`/`expel` газа выбирают глубину. У поверхности свет и воздух, у дна останки; каждый гребок тем дороже, чем глубже (подробно — «Вода» в docs/SIMULATION.md). `dig` переносит блок целиком; `pile` собирает блок из одинаковых твёрдых молекул; `grow` выделяет агрегат из четырёх имеющихся молекул тела. Древесина не является особым материалом. Связи колонии требуют взаимного согласия. Способности и устойчивые цепочки возникают через случайный код и отбор.

## Текущий масштаб модели

Это конечная искусственная химия и приближённая механика вокселей. Решётка представлена составом, связностью и параметром порядка; явных координат атомов и расчёта упругих деформаций нет. Опорный граф выбирает один сильнейший путь на блок и может консервативно разрушать свод, который выдержал бы более точный расчёт. Вода и атмосфера пока поверхностные (в воде есть плавучесть, глубина и свет по глубине, но нет течений); самостоятельного климата пещер нет. Все детали и направления оптимизации перечислены в [docs/SIMULATION.md](docs/SIMULATION.md).
