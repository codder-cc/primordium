# Primordium: contributor guidelines

- This is **Godot 4.3 C# / .NET 10** (both projects target `net10.0`; .NET SDK 10 is required), despite the parent directory being named `unity`. The `src/Sim` core does not depend on Godot.
- Start by reading `README.md`, `docs/SIMULATION.md` and the latest entry in `docs/CHANGELOG.md`.
- The project's premise: procedural matter and evolution, with no predefined rocks or abilities. Do not bring back sand/clay/coal tables, free nutrition, conversion of energy into molecules, or transmutation of elements.
- **Conservation of atoms.** The composition of every chemical reaction must conserve `Chemistry.Atoms`. Derive mass from composition. Also check fractional quantities, protein substrate and buried remains. Fractional matter (`C`, `Burial.Matter`, `Pend`, `Enzyme.Matter`) is `Qty` fixed point: move the same `Qty` from pool to pool, never a float computed from a pool (otherwise atom drift from rounding returns, see CHANGELOG (7)).
- **Geometry.** Do not shift an entire column of blocks when mining. `Height` is an upper bound; there may be voids inside. A creature's height is `Agent.Z`. Change geometry only through `World.Matter`/`World.Terrain`/`World.Structure` methods, invalidating strength and support.
- **Parallel stepping.** Creatures step in parallel on 32×32 tiles with checkerboard colouring (`World.Step`). Code that runs in their phase must follow the contract in `docs/SIMULATION.md` ("Performance and threads"): write only within ~7 cells; anything global goes through `MarkDirty`, `NewId`, `Ctx.Newborn`/`Ctx.Firsts`, `Interlocked`; randomness only from `Rng`. Defer long-range mechanics into `Ctx` and apply them after the phase. Determinism is checked by `--self-test`.
- **Water height.** In water a creature has, in addition to its floor `Z`, a height above the bottom `Lift` (`World.Water.cs`). When repositioning a body, preserve its absolute height via `SetLift` (as `Move`, `Shift`, `Born` do), and compute proximity and reach from `Z + Lift`. New vertical commands must not take values away from existing ones: land mobility is sensitive to this (see CHANGELOG, "water").
- **Build and test** after significant changes: `dotnet build --no-restore -p:UseSharedCompilation=false`; `dotnet run -c Release --project tools/bench -- --self-test`. For long runs use `--audit` and several seeds. For speed: the `stages`/`detail`/`agent tiles` profile lines and `--ops`.
- **Determinism comparisons.** The world is deterministic — compare an optimisation on the same trajectory (same seed and parameters) before/after. Do not treat the speed of different world versions as the same workload: new chemistry changes population, genomes and the number of collapses. Record seed, population, ticks, `Prof` stages, Release mode, device and command.
- **Do not rebuild a DLL that a long run is currently executing.** If work on the code continues, copy the DLL, runtimeconfig and deps to a separate temp directory before launching.
- **Documentation.** When a mechanic changes, update `docs/CHANGELOG.md` and its description/limitations in `docs/SIMULATION.md`. State what was verified and what remains an approximation.
- **Save sync.** **New world or body state** (a field of `World`, `Agent`, `Burial`, `Vent`…) that survives a tick must be added to `World.Save.cs` (`SyncScalars`/`SyncCells`/`SyncAgent`…: a single field list for both writing and reading), otherwise a loaded world will diverge from the original. On an incompatible format change, increment `World.SaveVersion`. The `save/load` test compares the continuation after loading with the original world.
- **ParamRegistry.** A **new tunable quantity** is a static field of `P` with an entry in `ParamRegistry` (group, description, range, step, `Live`); without an entry the registry throws. If anything is cached from it, specify a `ParamEffect` and handle it in `World.ApplyParamChanges`. Core random numbers come only from `SimRng` (`World.Rng`), never `System.Random`.
- **Energy flow accounting.** A **new energy flow** (a path where chemical energy appears, disappears, arrives from outside or goes into heat: a new reaction, expenditure, import, a multiplier law) must be recorded in the `World.Energy` budget (`Flows[F…]`; if needed, a new flow in `FlowNames` within inputs/outputs and a new save version) and have a probe in `EnergyRegression`/`RegressionLaws`. The budget is checked by `--self-test`, `--audit` and `--long-test`; drift above tolerance is a bug, not noise.
